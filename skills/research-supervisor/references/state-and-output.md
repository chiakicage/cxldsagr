# 研究产物与更新约定

路径均相对项目根目录。维护一份当前状态，不生成 `state-v2/final-final` 等竞争版本。
首次运行先填当前已知内容。Supervisor 维护状态与下一步任务；呈现用的叙事由其他 agent 完成。

## 人可以直接编辑的两个入口

| 文件 | 作用 |
|---|---|
| `docs/status.md` | 当前研究状态的主入口，四环节 checklist、具体卡点、下一步导航 |
| `docs/roadmap.md` | 当前接下来要做什么，以及对应哪些研究条目 |

`status.md` 记录研究判断与缺口；`roadmap.md` 只列当前待做或进行中的任务。
人修改任一文件时，核对其含义并同步受影响的对应内容；不要机械地用旧状态覆盖新修正。
遇到实质矛盾，展示具体分歧供讨论，保留无争议内容，不自动推定较新时间戳就是研究结论。

### 状态表

开头简述当前研究起点、研究范围和最大的未决问题；注明更新时间。
按四环节分组，用 `1.1`、`2.1` 等稳定编号标识子项。可采用：

| 条目 / 要回答的问题 | 当前理解 | 状态与具体缺口 |
|---|---|---|
| 1.1 研究什么任务与场景？ | 当前候选表述，允许未知 | 成熟度；最具体的卡点 |

每个大环节有一个可核对的研究问题和勾选框：

- 任务与场景：是否能说明服务需求、研究对象和目标？
- Baseline/Motivation：是否覆盖主要相关方案并量化其关键取舍？
- Challenge/Design：是否能解释困难、设计对应关系和技术区别？
- Evaluation：是否已用整体比较与机制实验回答研究主张？

勾选表示当前范围内这一项已建立，且能说明依据；不能因为文档写完或子任务结束就勾选。
不要因缺少新一轮用户确认而机械地取消已有支持。状态用自然语言，如待明确、候选、待验证、
部分支持、已有支持、需要修订。需要时用一句话说明支持到哪里。

在表后汇总少量主要卡点：涉及哪些条目、卡在哪里、为什么影响研究、对应哪项任务。
“需要更多实验”“场景未完成”必须进一步具体化。
证据可以简述为研究发现，详细来源集中在内部索引，避免使表格成为实验账本。

### 下一步任务

用简短列表或表格，每项一行：稳定任务 ID、具体下一步动作、要得到的结果、对应研究条目。
按当前优先级排列；只有确实影响行动时才补一句依赖或卡点。任务多项影响时注明主研究条目。
不为每项重复展开背景、类型、预期交付、可能影响和完成边界；详细内容在派发执行任务时给出。
只保留当前待做或进行中的工作；完成或取消后移出 roadmap，保留其他任务的原编号。
研究发现回写状态表，重要变化简记到内部 `updates.md`，执行历史由对应 agent 维护。

任务结束不等于研究判断成立。建议任务不冒充正在执行或已经排期。
下一步只是建议时明确标明，读取任务清单不构成执行全部任务的指令。
详细命令和执行检查放在 `docs/agents/<agent-or-task>/`，或引用对应实验目录的现有说明。
KDA/编码执行者维护 `docs/agents/kda/<task>/`；实验、文献、写作执行者按任务需要建立内部材料。
这些角色是按需分工，不要求安装或生成整套新 skill。Supervisor 维护研究层的意义与任务关联。

## 内部依据：按需读取

- `docs/agents/research-supervisor/sources.md`：记录来源位置、相关条目、能支持和不能支持的判断。
  初次只读仓库报告时写“已有报告记载，本轮未重跑”；假设不能列成实测事实。
- `docs/agents/research-supervisor/updates.md`：只记录重要研究修正，包括用户修正、被排除的解释及理由。
  保留条目编号和受影响任务；不复制整段对话或所有工具输出。

两者服务于恢复上下文和核验。原始数据和实验报告仍由既有项目目录维护；
不在这里保存 GPU 测试结果、原始 profiler 文件或失效实验副本。

## 例子：一次探索如何更新状态

假设任务是在某个候选模型上估算 KV 容量，映射当前表中的 `1.2 模型`、`1.4 服务负载`、
`2.2 HBM 问题`。实际使用时查阅当前条目编号，不直接套用示例编号。
估算发现一部分规模可能超过 HBM，只能更新为“容量估算提示这一范围需要进一步验证”；
serving 效率受限和 overlap 的价值仍待检验。若合理范围内 HBM 足够，则记录这项反证，
重新考虑该范围的 motivation，不默默增加负载来使已有设计获胜。

人把场景从“真实推荐模型”修正为“先研究 GR 风格的系统负载”时，更新第一环的当前范围、
第二环的对比口径、第四环能回答的问题；实际推荐效果仍是未验证事项。
这种选择可以推进工作，但不升级为已经证明场景代表性。
