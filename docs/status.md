## 2. SOTA baseline 与 Motivation

- [ ] 覆盖主要相关方案，讲清它们的取舍，并量化目标场景中的关键问题。

当前候选论证是：**全 HBM 的容量约束 → CPU DRAM offload 的取数等待 → dense prefetch
的冗余 → sparse fetch 的重叠困难**。这是待分析和验证的思路线索，各环节尚未整体成立。

| 条目 / 要回答的问题 | 当前理解 | 状态与具体缺口 |
|---|---|---|
| **2.1 主要 baseline 是否覆盖？** | 全 HBM、串行 offload、dense prefetch、sparse fetch 是需要考察的方案；ECHO 是重点具体工作 | **待补全。** 尚未完成面向候选场景的 SOTA 覆盖和真实取舍关系梳理；这些方案不预设为历史演进顺序 |
| **2.2 全 HBM 的问题是什么？** | KV 容量可能限制容纳的用户/请求规模，进而影响 serving 效率 | **待验证。** 需要在合理的模型与负载规模下说明容量如何影响服务，现有单请求计算报告不能回答这一点 |
| **2.3 CPU DRAM offload 的问题是什么？** | 可以提供更大的 KV 存储空间，但串行 fetch 可能形成额外等待 | **候选解释。** 目标场景中取数等待的规模和重要性尚未建立；不把所有 offload 方案都视为串行 |
| **2.4 Dense prefetch 的问题是什么？** | 提前取数可能获得重叠机会，也可能搬运最终不会使用的 KV | **待验证。** 需要量化冗余与提前取数之间的取舍，以及这种取舍对服务的影响 |
| **2.5 与 ECHO 如何比较？** | 项目已有 ECHO 的 indexer/prefetch 融合实现与分析基础；当前 NOSA 设计融合 fetch/attention | **待厘清。** 当前 ECHO 与 NOSA 报告的模型和执行范围不同，尚未形成目标场景中的直接比较；需说明 ECHO 已解决什么、剩余问题及可比方式 |
