# 重要研究理解与修正

这里只记影响研究解释或任务选择的变化。文档维护和具体工具输出不逐条记录。

## 2026-10-02：ECHO/DeepSeek baseline 有效性退回待修正

- **来自研究者：**ECHO 实现的 MFU 和 cache 策略存在问题，baseline 对比不太正确；
  DeepSeek 当前实现的 MFU 也不太正确。
- **原判断的问题：**此前依据数值与计量审计，将 DeepSeek 模型内对照写成“可比”，
  并用旧 MFU 和延迟排名讨论实现瓶颈与 ECHO 取舍，超出了现有证据。
- **修正：**区分接口已实现、数值一致与 baseline 合理。相关 MFU、性能归因和方案排名
  暂停用于结论，具体实现问题、MFU 口径及 cache 策略需审计、修正和新 run 复测。
  当前代码的预取主动 eviction 与 cache scratch 计量缺口提供审计起点，不等于已确认
  全部根因或量化影响。原 run 和素材保留至替换验收完成；本轮不改旧数字、不声称已修复。
- **保留判断：**跨请求历史复用和串行多用户执行已实现；NOSA 仍无有限页级 slots。
  原用户规模与复访压力问题、GR 场景代表性和稳定服务收益均未解决，独立 NOSA 局部
  结果不自动失效。顺序负载 run 01 的源码身份失败也没有产生有效替换结果。
- **影响：**2.1、2.4、2.5、3.3、4.1；T-008 提到优先位置，T-003 根据修正后基线继续。
  依据见 [S-014](sources.md)，本轮没有新 GPU 性能测量。

## 2026-10-02：用户明确从已有热度独立抽样，取消复访上限

- **来自研究者：**使用现有用户访问次数构造概率分布，再随机采样总计 T 次；可取消
  每用户最多 8 次限制。实际用户数与复访情况应从结果中统计。
- **修正：**撤回执行者加入的 4N 配额、最少一次复访和原始时间戳前置要求。现有累计
  曲线差分可近似得到逐用户概率；只需要明确概率向量的底层用户池，不预先声称实际人数。
- **工程：**保留已有 weighted IID 采样，入口默认无 cap，补充实际复访用户和逐用户
  次数。旧有界报告仍按其原始参数保留，改动后未运行新 GPU。
- **影响：**1.3、1.4、2.2、4.1、4.3 与 T-006；依据见 [S-013](sources.md)。

## 2026-10-02：研究者提出从已有数据采样复访

- **来自研究者：**“这个复访能否用已有的数据集来采样？”
- **新增核对：**仓库现存 Amazon 热度材料来自每用户时间排名和累计次数，不能恢复跨用户
  全局顺序；旧原始数据路径当前不可访问。公开 UserBehavior 是可考察的行为数据源，
  本次只核实官方介绍，尚未取得原始数据或验证字段。
- **修正：**4N 全局打散保留为合成对照候选。优先取得 user/timestamp 行为数据，固定窗
  内抽实际复访的 N 名用户，每人最多保留 9 次请求且保持原顺序，复访次数由数据决定。
  真实数据采样不强制 25% 首访；筛用户及封顶对复用距离的影响必须披露。具体数据集和
  事件映射仍是建议，未记录为研究者已采纳。
- **影响：**1.3、1.4、2.2、4.1、4.3，更新 T-006 的下一步；没有新 GPU 结果。
  依据见 [S-012](sources.md) 和 [数据轨迹协议](../system/gr_serving_dataset_trace.md)。

## 2026-10-02：研究者否定名义用户规模，要求有效的复访 miss

- **来自研究者：**“配置的用户数根本没有意义”，并明确“没有复访 miss 完全没有意义”。
- **原判断的问题：**此前用固定 6/32 请求抽样越来越大的用户池，再把配置人数作为规模横轴。
  数值和计量审计证明了这些请求被正确执行，却没有证明它们能回答容量与扩展问题；
  单独披露实际覆盖不足不能弥补实验设计缺陷。
- **修正：**撤回旧请求构造支持用户规模扩展或容量主实验的解释。16K 的 13 次 miss 仅是
  旧轨迹的已观测事件；4K/64K 与 DeepSeek 零复访 miss 的主对照没有检验容量收益。
  原数值、LRU 记录和内核区间仍限于其实际输入，不冒充新负载结果。按实验替换规则，
  先补测再替换受影响的规模图和结论，不将简单改名作为新实验。
- **新候选：**N 表示确实复访的活跃用户。固定总复访数为 3N，以热度分配每人 1–8 次，
  加上首访共 4N 个请求，完整多重集合全局打散。以实际不同用户复用距离检查压力，
  主点覆盖 HBM miss/offload hit 及两者均 miss；全命中只作机制控制，不作容量主结果。
  这是执行者提出的受控负载，尚未由研究者确认，也未实现或运行模型。
- **时长约束：**减少完整 GPU 实验点，不再通过削减请求数破坏用户覆盖。现有模型成本下，
  原七档全覆盖与两模型八方案不能在约 30 分钟内完成；成本仅作规划估计，非新实测或严格下界。
- **影响：**1.4、2.2、4.1、4.3；T-006 提到当前优先位置，主条目改为 1.4。
  依据见 [S-011](sources.md)、[新负载协议](../system/gr_serving_workload_redesign.md)和
  [可行性分析](../system/gr_serving_workload_feasibility.md)。

## 2026-10-02：完成有界 GR serving，对容量与重叠分别判断

- **原判断：**跨请求 KV 复用和服务测量尚未建立，HBM 容量影响只能作为候选解释。
- **新证据：**按用户指定的两模型、七档用户、最多八次复访及三档固定历史，完成跨请求
  session LRU 和四方案串行对照。16K NOSA 在统一配额下，HBM 的 63 次复访有 13 次重建，
  offload 均命中；但全请求均值仍为 HBM 最低。4K/64K 及 DeepSeek 没有实测复访 miss。
- **修正：**1.4 的工程与测量能力升级为已有支持；2.2 获得有限配额/轨迹下的容量证据，
  4.1 不升级为普遍整体服务收益。配置人数不等于实际活跃人数；为控时使用的 64K 六请求
  轨迹有四档无复访，不补造或以首访代替。每档约 30 分钟是执行者已披露的解释，非用户确认。
- **机制判断：**NOSA overlap 相对串行 sparse 在 20/21 个配置降低全请求均值，但复访
  均值未稳定改善。新 serving profile 的九个复访样本双比率全部低于 90%；这不否定
  已测得的全请求改善，也不足以解释冷历史和复访之间的差异。Dense 预取可快于 sparse，
  不能用冗余字节或局部重叠单独推出延迟排名。旧 64K+1K 单层结果的有效范围保留。
- **未改变：**合成 GR 内容的代表性、真实推荐模型/数据、目标服务混合仍未确定；DeepSeek
  是约 8B checkpoint 替身，NOSA 没有有限 token/page slots，不新增 CXL/RDMA 前提。
- **影响与任务：**1.2、1.4、1.5、2.1–2.5、3.1、3.2、4.1–4.3。T-004 首轮容量估算/实测
  和 T-005 最小方案对照已完成并移出 roadmap；这不表示其 Motivation 已全面建立。
  新的 T-006 针对复访覆盖、重用距离和预算敏感性，T-007 针对请求开销及 candidate 长度；
  保留 T-002 场景依据与 T-003 ECHO 可比性。后续任务仅建议，未自动执行。
- **依据：**[S-008–S-010](sources.md)、
  [完整实验](../../../experiments/gr_serving/README.md)、[验收记录](../system/gr_serving_review.md)。

- **来自研究者：**presentation 始终围绕实验室四环节，内部运行核验与给人的研究叙事分层。
- **修正：**研究状态以问题、baseline、challenge/design、evaluation 为中心；
  不再把数值/运行验证清单作为研究呈现结构。
- **影响：**全部条目；状态表、叙事、任务和内部材料分开维护。

- **来自研究者：**当前从 sparse KV fetching 与 sparse attention overlap 的 design 出发寻找场景；
  sparse attention GR serving 尚不确定，需要逐步补全模型、数据及负载。
- **修正：**允许第一环未知时继续第三环的探索；不要求按最早未完成环节逐一通过。
  人的修正会改变后续工作；agent 提出的场景路线不自动成为已采纳的选择。
- **影响：**1.1–1.5、3.1–3.3；T-002 与 T-005 可按各自已知部分推进。

- **来自研究者：**当前先关注 CPU DRAM，CXL/RDMA 不一定重要。
- **修正：**本轮范围设为 HBM 与 CPU DRAM，未为 CXL/RDMA 建立任务或验证前提。
- **影响：**2.2–2.5、4.1；后续范围变化仍由研究者输入更新。
